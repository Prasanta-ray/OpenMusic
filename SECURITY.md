# Security Policy

## Supported Versions

Only the latest stable release of OpenMusic is supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

The OpenMusic maintainers take security and user privacy seriously. If you discover a security vulnerability, please do NOT file a public issue.

Instead, please report the vulnerability confidentially via one of the following methods:

1. **GitHub Private Security Advisory**:
   * Navigate to the **Security** tab of the repository on GitHub.
   * Click **Report a vulnerability** to open a draft private advisory.
2. **Email Maintainers**:
   * If private advisories are unavailable, email `security@openmusic.internal` with full disclosure details.

### What to Include in Your Report
* Description of the vulnerability and its potential impact.
* Detailed steps to reproduce or a Proof of Concept (PoC).
* Affected versions and device/Android environment details.
* Any potential mitigations or patches you have developed.

### Disclosure Timeline
* **Acknowledgement**: Within 48 hours of initial report.
* **Assessment & Fix**: Typically within 7–14 days depending on complexity.
* **Public Release**: A patched release will be made available simultaneously with a public advisory credit.
